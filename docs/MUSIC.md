# 音乐库与后续音频

Focus 右侧的 Music 一行保留播放开关和音量，新增四格图标打开 Music room。较高窗口下还显示当前曲目的小播放器；矮屏保留紧凑入口，分类和完整控制在弹窗里，避免撑大页面。

## 已有的界面

| 分类 | 当前内容 |
| --- | --- |
| Soft music（轻音乐） | 原有 Warm Focus 可播放，预留一个位置 |
| Groove（律动） | 预留两个位置，显示 Coming soon |
| White noise（白噪音） | 预留两个位置，显示 Coming soon |

分类用不同的柔和色块与像素图标区分，窗口沿用游戏里的紫色斜边和旧式桌面标题栏。未添加音频的曲目明确不可播放，不会请求不存在的文件，也不会用别的声音冒充。

播放器支持播放/暂停、可用曲目的上一首/下一首、进度拖动、单曲循环或顺序循环，以及与侧栏同步的音量。只有一首可用音乐时，上下首按钮不可点。选择曲目会开始播放；仅打开窗口或浏览分类不会播放。音乐跨游戏页面持续，开关音乐和浏览分类不改变学习计时。

音量、选中的曲目和循环偏好保存在原游戏存档里。刷新不会自动播放。清空聊天与音乐无关。当前只播放一首背景音乐，不叠加多条声音。

## 做好音频后怎么放进去

你之后可以直接把文件交给开发者接入。对应配置集中在根目录 [music-catalog.js](../music-catalog.js)，不需要改计时逻辑或重新设计界面。

1. 将音频放到 `assets/audio/`，建议用独立文件名的 MP3。
2. 找到对应预留曲目，修改标题，将 `src: null` 改为真实文件路径。例如律动的第一首：

```json
{
  "id": "groove-one",
  "category": "groove",
  "title": "你制作的曲目名称",
  "description": "一句简短的介绍",
  "src": "assets/audio/your-groove.mp3"
}
```

3. `category` 可选 `soft`、`groove`、`noise`。也可以在 `categories` 中加新类别，然后给曲目填写同一 ID。每首曲目的 `id` 应唯一且稳定，用来恢复用户选择。
4. `durationSeconds` 可选；未填时开始播放后读取文件的实际时长。没有文件就保持 `src: null`。
5. 更新下载版，再提交源码、目录和音频：

```sh
python scripts/build_standalone.py
```

构建会自动把所有已经配置的音频内嵌到三个下载入口。默认曲目仅存一份，目录与播放器共用它；其余预留位置不会增加音频体积。若声明了文件路径但实际文件不存在，构建会报错，避免发出缺文件的下载版。

目录中的数据必须保留为严格 JSON，使用双引号、不加尾随逗号；这是离线构建读取目录的格式。支持本地 `.mp3`、`.wav`、`.ogg`、`.m4a`，目录应保持在 `assets/audio/` 内。

## 本地查看与验证

```sh
npm run dev
python tests/test_music.py
python tests/test_viewport.py
```

Node 开发服务支持音频 Range 请求，可真实拖动进度。若使用不支持 Range 的静态服务，浏览器可能只允许从头播放；此时进度拖动会保持不可用，不假装已经跳到选定位置。

`test_music.py` 使用实际 MP3 验证播放、暂停、拖动、音量、循环、曲目扩充、自动切下一首、刷新不自动播放、分类占位、错误重试、计时不被打断、手机窗口和断网单文件。临时 WAV 仅用于验证未来文件的打包，不是发布的新曲目。
