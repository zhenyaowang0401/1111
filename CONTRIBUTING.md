# Contributing

## Making changes

1. Edit the root HTML, CSS, or JavaScript source files.
2. Check the interface and interactions using a local HTTP server.
3. Run `python3 scripts/build_standalone.py` to update the standalone web builds.
4. Run the checks relevant to your changes; see the [testing guide](docs/TESTING.md). Before a release, complete the applicable browser regressions, API contract checks, and reward checks.
5. Review `git diff` and commit source changes, documentation, and updated standalone files together.

Static web gameplay needs no npm installation. Python test dependencies are separate from game runtime dependencies. The local API server and desktop tooling use Node.js 22; run `npm ci` before using them. Real credentials belong only in local environment files or server environment settings.

## Maintenance guidelines

- Edit source files rather than only modifying generated HTML. Desktop web assets are generated by `npm run desktop:prepare`.
- Preserve existing saves when changing storage schemas. Retain compatible keys or provide an explicit migration.
- Keep Study, Work, Break, and developer-demo statistics distinct.
- Embedded previews must remain usable when native form submission or History API changes are restricted.
- Use shared character rendering across setup, the mine, home, friends, and floating windows.
- Clearly label any example data or unfinished functionality.
- Never commit local saves, credentials, browser profiles, temporary test files, or installer binaries.
- Preserve the repository's original media unless a task explicitly calls for changing it.

## Commit and release descriptions

Describe the behavior users will observe and the validation actually performed. Do not describe unimplemented online features, unrun tests, or incomplete deployments as available.

Write public project descriptions and release notes in English. Keep links and installer filenames accurate. Desktop release notes live in `desktop/RELEASE_NOTES.md`; the release-description workflow syncs updates to the published release matching `package.json`.
